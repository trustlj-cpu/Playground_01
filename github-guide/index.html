      Chapter 1

      깃허브가 뭔가요

      코드와 문서를 버전별로 저장하고, 다른 사람과 함께 고치는 온라인 작업실입니다.

      깃(Git)과 깃허브는 다릅니다

      Git은 내 컴퓨터에서 파일의 변경 이력을 기록하는 프로그램이고, GitHub는 그 기록을 인터넷에 올려 공유·협업하는 서비스입니다.

      • “Add a README file” 체크하면 바로 시작

      Chapter 2

      꼭 알아야 할 용어

      화면에 보이는 단어 대부분이 여기 있습니다.

      Repository (저장소)
      프로젝트 폴더 하나. 파일과 전체 변경 이력이 들어 있습니다.
      Commit (커밋)
      변경 사항을 메시지와 함께 저장한 한 시점의 스냅샷.
      Branch (브랜치)
      원본을 건드리지 않고 따로 작업하는 갈래. 기본은 main.
      Pull Request (PR)
      “제 브랜치를 합쳐 주세요”라는 요청. 리뷰와 토론이 여기서 일어납니다.
      Issue (이슈)
      버그 신고, 기능 제안, 할 일 메모를 남기는 게시판.
      Fork (포크)
      남의 저장소를 내 계정으로 통째로 복사해 자유롭게 고치는 것.
      Star (스타)
      북마크이자 ‘좋아요’. 스타 수는 인기의 대략적인 지표입니다.
      Actions
      푸시·PR 같은 이벤트에 맞춰 테스트·배포를 자동 실행하는 기능.
      Release (릴리스)
      배포용 버전 묶음. 설치 파일은 보통 여기서 내려받습니다.
      Chapter 3

      개발자의 하루 흐름

      브랜치를 만들고, 커밋하고, PR로 합치는 기본 루프입니다.

      명령하는 일
      git clone <url>저장소를 내 컴퓨터로 복제
      git switch -c feat/login새 브랜치를 만들고 이동
      git add -p변경 사항을 조각별로 골라 스테이징
      git commit -m "로그인 폼 추가"스냅샷 저장
      git push -u origin feat/login브랜치를 깃허브에 올리기
      gh pr create --fillGitHub CLI로 바로 PR 열기
      git pull --rebase최신 변경을 받아 내 커밋을 위에 다시 쌓기
      git restore <file>커밋 전 수정을 되돌리기

      좋은 PR의 조건

      • 한 PR에는 한 가지 목적만
      • 설명에 “왜”와 테스트 방법 적기
      • 본문에 Closes #12 쓰면 머지 시 이슈 자동 종료
      • Draft PR로 일찍 공유하고 피드백 받기
