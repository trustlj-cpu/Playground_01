# 판 작성 스펙 (JSON) — 에이전트용

너는 **본문 JSON만** 쓴다. HTML·CSS·스크립트·고정 문구(라벨, 푸터, 팝업 UI)는 `render.py` 가 그 나라 직전 판에서 가져온다. HTML 을 쓰지 마라. 템플릿 HTML 을 읽지 마라.

## 편집 원칙 (사장님 2026-10-18, 초반 호(No.1~10대 초반) 방식 — 철저히 지킨다)
- **같은 판 안 중복 기사 절대 금지 (사장님 2026-10-19).** 본문 5개 기사·짧게 보는 오늘(index 5)·짧게 더(briefs)는 모두 서로 다른 소식이어야 한다. index·briefs에 본문 기사와 같은 사건을 다시 쓰지 않고, briefs에 index 항목을 다시 쓰지 않는다. check_spec 이 겹침을 오류로 잡는다.
- **1면 기사 본문(`paras`)은 우리가 직접 쓰는 기사다 — 초회판(No.1~5)의 문체로 쓴다 (사장님 2026-10-29: "출처에 따르면…" 식으로 보도자료 읽어주는 문체 금지).** 확인된 사실은 **우리 목소리로 단정해서 쓴다**("합동참모본부는 5일 최종 조사 결과를 발표했다", "영업이익이 107조 4천억 원이다"). 문장마다 매체 이름을 붙여 "연합뉴스는 …고 전했다. 조선일보는 …고 보도했다."로 잇는 나열은 **금지**. 여러 매체 내용을 한 사건의 흐름(무슨 일 → 숫자 → 배경 → 엇갈리는 점 → 아직 모르는 것)으로 엮고, 문장은 인과·시간으로 이어 읽히게 쓴다. **다른 신문사·방송사·통신사 이름과 그들의 기사·제목·평가는 글에 절대 넣지 않는다**(사장님 2026-10-29 재지시: "다른 신문사 글에 인용하지 말라"). "연합뉴스는", "조선일보 속보는", "한국경제가 전했다", "…라고 평가했다" 모두 금지. 인용·입장은 **말한 사람·기관**(우주항공청, 이억원 금융위원장, SK에너지)만 밝힌다. 수치가 엇갈리면 공식 발표(회사 공시·정부 발표) 기준으로 쓰고, 공식 수치가 없으면 "집계마다 조금씩 다르다"고만 쓴다. 한 곳에서만 나온 내용은 쓰지 않거나 "…는 아직 공식 확인되지 않았다"로 쓴다. 출처는 팝업 `src`·`extras.src`·`verify`(✓ N매체) 에만 둔다.
- 좋은 본문의 모양(초회판): 첫 문장에 무슨 일인지(누가·언제·무엇), 이어서 숫자, 숫자는 독자가 느끼게 환산("매출 100원 가운데 55원이 본업 이익으로 남았다는 뜻이다"), 어려운 말은 그 자리에서 쉬운 말로 한 번 풀기, 지난 호·어제 일과 이어지면 한 문장으로 잇기, 끝은 아직 정해지지 않은 것·다음 일정. 우리 의견·평가·전망·조언·교훈은 본문에 넣지 않는다(팝업 몫). 사실을 쉽게 풀어 주는 설명과 숫자 환산은 본문에 넣는다.
- **우리 생각은 팝업에만 쓴다.** 팝업 = what(사실 — 매체 이름 없이, 말한 사람·기관만) → why(왜 중요한가: 메커니즘·배경) → me(나에게는) → a·b(**두 가지 시선**: 보도에 실제로 나온 서로 다른 시각을 각 2~3문장씩 공정하게) → say(데일리드롭 생각: 확인된 것과 아닌 것을 가르고 오늘 볼 것을 구체적으로, 2~4문장) → src(구체적 매체와 날짜).
- 본문은 **자료에 대한 말을 하지 않는다.** "수집된 기사에는 나오지 않았다", "이번 호는 …까지 확인된 보도만 담았다", "독자가 기억할 점은", "~하는 편이 안전하다", "feed", "Jev" 같은 문장 금지. 확인 안 된 것은 사실 문장 끝에 "…는 확인되지 않았다" 한 문장으로만(보통 `verify` 칸에 쓴다).
- 모양: 리드 = deck 1줄 + **본문 2문단**(한국어 약 900~1100자, 일본어·중국어 약 750~950자, 라틴 문자권 약 330~450단어), 나머지 기사 = 1~2문단(한국어 약 400~600자, 일본어·중국어 약 350~500자, 라틴 약 130~230단어). 문단을 쪼개 늘리지 마라(리드 정확히 2문단). 새 소식 한 건 한 건이 선명해야지, 배경 설명으로 분량을 채우지 마라.
- 사실은 반드시 **웹 검색(WebSearch/WebFetch)으로 서로 다른 매체 2곳 이상**에서 확인한다. 피드 제목·요약(110자)만으로 쓰지 마라. 기사 문장을 베끼지 말고 우리 말로 요약한다. 확인 못 한 이름·직함·연도·숫자는 쓰지 않는다.

## 출력
`{OUT}_spec.json` 한 파일(UTF-8). 쓴 뒤 `python3 /home/user/Playground_01/ops/autoed/check_spec.py <파일>` 이 `ok` 를 출력할 때까지 고쳐라.

## 단신 (사장님 2026-10-20)
- 단신 칸은 "짧게 보는 오늘"(index 5건, 제목·두 문장·팝업) 하나뿐. "짧게 더"(briefs)는 쓰지 않는다. stories[4]는 본문 2문단 + nums(3칸) 또는 word로 채운다.

## 일관성 기준 (사장님 2026-10-19 — 6~9호가 기준)
- (10/21) verify/tag 의 "✓ N" 은 그 팝업 src 의 매체 항목 수(· 로 구분)와 같아야 한다. 헤드라인의 숫자는 본문 또는 팝업 what 에 그대로 있어야 한다. check_spec 이 막는다.
- 모든 판·모든 나라가 같은 칸을 같은 밀도로 채운다: a·b 10/10, src 는 "매체(무엇, 날짜) · …" (Google News 금지), 용어 15~40(어려운 것만), 인플루언서 4~6, 원문 링크 10/10. check_spec 이 하나라도 어긋나면 막는다.

## 규칙 (사장님 방침)
- 사실은 **서로 다른 매체 2곳 이상**에서 확인된 것만. 한 곳뿐이면 본문에 매체 이름을 쓰지 말고 `verify` 에 "1매체"로 적는다. 숫자는 출처를 붙인다. 기사 문장을 베끼지 마라.
- 사건 날짜와 보도 날짜를 구분. 판 날짜 05:00(현지) 이후 일은 "오늘 볼 것"에만.
- 지표(ears/markets)는 시세 표의 ts 가 마감 이후·판 시각 이전인 것만. 장중 값 금지. 불확실하면 "—".
- **DailyDrop 이 어떻게 만들어지는지, 어떤 도구·AI 가 쓰는지는 어디에도 쓰지 마라.**
- 용어사전(glossary)은 **어려운 용어만**(사장님 10/25): 법·제도·금융·경제·과학·기술·안보의 개념과 약어처럼 일반 독자가 설명 없이는 모르는 것. 기업명·매체명·인명·지명·스포츠 팀·누구나 아는 기관은 넣지 않는다(분야 f 도 기업·미디어·인물·지리·스포츠로 쓰지 말 것 — check_spec 가 막는다). 뜻풀이가 한 줄로 끝나는 쉬운 말도 뺀다.
- 세계 뉴스는 `world_*.json` 의 해당 항목을 그 나라 말로 옮기고 그 나라 독자에게 맞게 각도만 바꿔라. 나라 뉴스에 집중.

## 석간(evening edition) 작성 시
작업 파일에 EVENING EDITION 이 적혀 있으면: spec 에 `"slot":"pm"` 추가, 날짜줄은 `No. N · Evening`(그 나라 말로), 호수는 그날 조간과 같다. 같은 날 조간 spec 과 같은 사건을 다시 쓰지 말고(새 전개일 때만, 제목에 그 전개를 쓴다) 나머지 규칙은 조간과 같다.
