# 한국판 읽어주기 — 앵커 원고 쓰기 (판마다 한 번, 한국판 편집이 끝난 뒤)

사장님 결정(바꾸지 말 것): 「한가지 원고로만 간다. 뉴스 방송용 원고로 실제 뉴스 앵커가 말하듯이 보도.」 「자연스럽게 뉴스앵커 원고처럼 말하는걸로 통일해.」
원고는 판마다 **하나**. 지면 글을 소리 내어 읽는 것이 아니라, 그 판의 기사를 **TV 뉴스 앵커가 보도하는 방송 원고로 다시 쓴다**.
「나에게는 / 이렇게 보는 쪽 / 저렇게 보는 쪽 / 데일리드롭의 생각」 칸은 넣지 않는다(사장님 기본값 가: 소식만 보도).

## 방송 짜임 (사장님 10/12, 한국어)
**기사(뉴스)만** 읽는다 — 용어 풀이·소문·인플루언서·볼 만한 것(what-to-watch) 칸은 읽지 않는다. 판의 기사를 전부 읽지 않고 **주요 기사만** 고른다.
순서(견본: `juha_1013.txt`):
1. **여는 말** — 인사 + 날짜·요일 + 데일리드롭 조간. 소식 개수 약속은 하지 않는다(몇 건 읽을지 판 기사 수와 다르다).
2. **시장 지표(indices)** — 여는 말 바로 다음, 언제나 가장 먼저: 코스피(수준·등락률·연속 하락/상승), 코스닥, 원 달러 환율. 판 머리 `ear` 칸과 시장 기사에 있는 값만. 이 문장들만 한 문장에 숫자 둘(수준+등락률)까지 허용.
3. **머리기사** — 반드시. 판의 첫 기사.
4. **주요 기사** — 본문이 길거나(문단 2개 이상, 또는 500자 이상) 비중 큰 기사는 반드시 넣고, 1면의 **분야(kick 첫 낱말)마다 한 번씩** 다룬다(시장 분야는 지표가 맡는다). 나머지는 건너뛴다.
5. **단신 1~3개** — 한 문장(많아야 두 문장)씩. 「이 밖의 소식은 짧게 전해 드립니다」로 묶어 넘기고 첫 단신에만 붙인다.
6. **닫는 말** — 짧게. 사실·시각 약속 없음.
죽음·재난을 다룬 기사는 단신 묶음보다 **뒤쪽(끝 가까이)** 에 둔다(뒤에 가벼운 말이 붙지 않게).

### 기사 사이를 잇는 말 (실제 뉴스 앵커처럼)
「다음은 증시 소식입니다」「정치 소식입니다」 같은 **분야 꼬리표 금지**(검사기가 막는다). 대신 다음 다섯 가지 중 하나를 쓴다. JSON 의 `bridge` 에 종류를 적는다.
- `follow` 이어받기: 앞 기사의 낱말·인물·상품을 받아 넘긴다. 예) 「코스피 변동성의 원인으로 지목된 상품을 두고 국회에서 사과가 나왔습니다.」 「인권을 둘러싼 소식이 하나 더 있습니다.」
- `shift` 자리 옮기기: 장소·화제를 옮긴다. 예) 「이번에는 중동으로 가 보겠습니다.」
- `impact` 영향 잇기: 판에 적힌 사실로 앞뒤를 잇는다. 예) 「같은 날 증시도 크게 흔들렸습니다.」 (원인을 판이 말하지 않았다면 인과로 쓰지 않고 「같은 날」처럼 시점으로만 잇는다)
- `group` 묶어 넘기기: 「이 밖의 소식은 짧게 전해 드립니다.」
- `none` 바로: 꼬리표 없이 곧장 다음 기사 첫 문장. 무거운 소식 뒤에는 이것만.
규칙: 넘어가는 말은 **한 문장**. **판에 없는 사실을 더하지 않는다**(고개를 숙였다·분위기 같은 묘사도 안 됨). 사망·재난 기사 바로 뒤에는 bridge `none`(transition 빈 문자열). 같은 종류를 **연달아 쓰지 않는다**(`none` 은 예외). 같은 문장을 판 안에서 겹쳐 쓰지 않는다. 머리기사의 transition 은 빈 문자열.

## 입력과 출력
- 읽을 것: `site/editions/<날짜>.html` (한국판). 1면 기사(`class="story" … data-id="…"`)의 분야·제목·부제·본문과, 파일 안 `const A = {…}` 의 같은 id 항목(`what`, `why`), 판 머리의 지수 칸(`class="ear"`). **사실은 이 파일 안에서만** 가져온다. 다른 날 판·기억·검색 결과는 쓰지 않는다.
- 쓸 것: `site/editions/anchor/<날짜>.json`

```json
{
  "date": "YYYY-MM-DD",
  "opening": "여는 말(1~2문장)",
  "indices": "시장 지표(3~6문장: 코스피·코스닥·원 달러)",
  "stories": [
    { "id": "<data-id>", "transition": "", "bridge": "none", "lines": ["문장", "…"] },
    { "id": "<data-id>", "transition": "넘어가는 말 한 문장", "bridge": "follow", "lines": ["…"] }
  ],
  "closing": "닫는 말(1~2문장)"
}
```
- `stories` 는 **고른 기사만**, 방송 순서대로(지면 순서가 아니어도 된다). 첫 기사는 지면의 머리기사. id 는 html 의 `data-id` 와 똑같이. 빠진 기사는 따로 적지 않는다.
- 빠진 기사도 지면의 재생 단추를 누르면 **지면 글자(제목·부제·본문)** 로 읽힌다(Worker 의 대체 읽기).
- `lines` 의 한 칸 = 한 문장(마침표로 끝남). 자막이 이 문장 단위로 넘어간다. 주요 기사 3~10문장, 단신 1~2문장.

## 기사 원고의 짜임 (괄괄이 방송 원고 분석 2287)
- **주요 기사**(본문이 긴 기사): 앵커 리드 1~2문장(누가 무엇을 했다 — 핵심) → 본문, 순서는 사실 → 누가 무슨 말을 했나 → 배경 → 쟁점 → 앞으로 볼 것. 전체 10문장 이하. 지표(indices)에서 이미 읽은 숫자는 되풀이하지 않는다.
- **단신**: 한 문장. 판의 `A[id].what` 이나 제목에서 사실을 가져와도 된다.

## 문장 규칙
1. 한 문장에 내용 하나. 40자 안팎, **60자를 넘기지 않는다**.
2. 출처는 **문장 앞에**: 「연합뉴스는 …라고 전했습니다」 「…에 따르면」. 괄호 속 매체 나열 `(연합뉴스·조선일보)` 는 읽지 않는다 — 원고에 괄호를 쓰지 않는다.
3. **한 문장에 숫자 하나**(시장 지표 문장만 수준+등락률 둘까지). 날짜(10월 12일)·시각(아홉 시 20분)·기간(1년 8개월)·한 금액(1억 7천만 원, 107조 4천억 원)은 하나로 센다. 둘 이상이면 문장을 나눈다.
4. 숫자·기호·영문 약어는 **읽는 말로**: `%`→퍼센트, `㎞`→킬로미터, `㎍/㎗`→데시리터당 ○마이크로그램, `S&P`→에스앤피, `SK`→에스케이, `SUV`→에스유브이, `AI`→에이아이, `NPR`→엔피알, `12·3`→십이삼, `원/달러`→원 달러, `1000만`→1천만, 세는 말은 고유어(쉰 차례, 다섯 개, 두 발, 아홉 시). 소수·큰 수는 숫자로 둔다(3.65퍼센트, 6,384.24, 199조 원) — 음성 엔진이 읽는다. 「2발」처럼 숫자+「발」은 엔진이 잘못 읽으니 반드시 「두 발」.
5. 말끝은 격식체 「~습니다/~입니다」. 같은 말끝을 세 번 잇지 않는다 — 「알려졌습니다 / 밝혔습니다 / 전했습니다 / 전망입니다 / 보입니다 / 주목됩니다 / ~입니다」를 섞는다. 「~했습니다」로 끝나는 문장이 세 번 이어지지 않게.
6. 쓰지 않는 것: 반말(~다.), 구어(~죠, ~거든요, ~잖아요), 질문 던지기(「왜일까요?」), 신문 제목식 끊기(「경찰, 국정원 압수수색」), 따옴표·괄호·가운뎃점, 감탄·평가(「충격적인」), 판에 없는 해석.
7. 날짜는 판 날짜 기준 상대 표현을 써도 된다(판이 13일이면 12일 = 「어제」, 12일 밤 = 「어젯밤」). 요일은 판 날짜의 요일.
8. 넘어가는 말: 위 「기사 사이를 잇는 말」을 따른다(분야 꼬리표 금지, 한 문장, 판에 있는 사실만).
9. 여는 말: 인사 + 날짜·요일 + 데일리드롭 조간. 닫는 말: 「오늘 데일리드롭 조간은 여기까지입니다」류. 사실·시각 약속을 넣지 않는다.

## 사실 충실(가장 중요)
- 이름·직함·기관·숫자·날짜는 **판 글에 있는 그대로**. 바꾸거나 반올림하지 않는다(쉰 차례 ↔ 50차례 처럼 읽는 말로 바꾸는 것만 허용).
- 판 글이 「확인되지 않았다」고 한 것은 그대로 「확인되지 않았습니다」. 주장은 주장으로(「…라고 주장했습니다」).
- 판 안에서 숫자가 서로 다르면(예: 사망자 수가 기사마다 다름) 그 숫자는 빼고 쓴다.
- 판에 없는 소속·당명·배경을 덧붙이지 않는다.

## 쓰고 나서 반드시
```
node site/anchor-check.js <날짜>
```
- `ERROR` 가 0이어야 한다(숫자·말로 쓴 숫자·영문 약어·고유명사가 판 글에 없거나, 60자 초과, 괄호·기호·영문, 반말, 같은 말끝 세 번, 한 문장 숫자 둘, 의견 코너, 그리고 짜임: 지표 없음, 머리기사 빠짐/첫 기사 아님, 긴 기사 빠짐, 꼬리표식 넘어가는 말, 넘어가는 말 두 문장 이상, bridge 종류 빠짐·불일치·연속, 사망·재난 기사 뒤 꼬리표). 1면 분야가 하나도 안 다뤄지거나 단신이 1~3개가 아니면 `warn`.
- `warn`(50자 넘는 문장)은 가능하면 나눈다.
- 마지막 줄 「판 글에 그대로 없는 낱말」 목록을 훑어, 동사 활용·연결 말이 아닌 **사실 낱말**(이름, 기관, 숫자 말)이 끼어 있으면 고친다.
- 그다음 `node site/build.js site/editions.json` 으로 빌드하면 `/<날짜>/tts.json` 의 `anchor` 로 실리고, 피드 Worker가 이 원고로 읽는다(매분 크론이 음성을 미리 만든다). 빌드는 날짜가 틀리거나 1면에 없는 id 가 있으면 멈춘다.
